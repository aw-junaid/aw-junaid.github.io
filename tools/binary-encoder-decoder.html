✦ How This Tool Works

What problem does this actually solve?

Binary is the layer underneath every protocol, file format, and register — but debugging it by hand is slow and error-prone. This tool converts text, integers, hex dumps, and floats to and from binary so you can inspect a byte stream from a packet capture, verify a checksum, debug a signed-integer bug, or understand why an IEEE-754 float doesn't round-trip exactly.

Why does the same number look different in big-endian vs little-endian?

Endianness only changes how a multi-byte integer's bytes are ordered in memory or on the wire — the underlying value is identical. Network protocols conventionally use big-endian ("network byte order"), while x86 and most ARM systems store integers little-endian internally, which is why byte order mismatches are a classic source of interoperability bugs.

What is two's-complement, and why does it matter?

Two's-complement is the standard way computers represent negative integers in binary: the most significant bit acts as a sign indicator, and negating a number is done by inverting all bits and adding one. It matters because the same bit pattern means a different value depending on whether it's interpreted as signed or unsigned — a frequent source of off-by-huge-number bugs when a value silently wraps around zero.

Why doesn't 0.1 encode exactly in IEEE-754?

IEEE-754 floating point represents numbers as a sign, exponent, and fraction in binary, and most decimal fractions — including 0.1 — cannot be expressed exactly as a finite sum of binary fractions, the same way 1/3 has no exact finite decimal form. The float encoder shows the actual stored bit pattern so you can see the rounding for yourself, which explains classic "why isn't 0.1 + 0.2 == 0.3" bugs.

What's the difference between parity and checksum here?

A parity bit is a single extra bit set so the total number of 1-bits in a byte is even or odd, catching simple single-bit transmission errors cheaply. An XOR checksum extends that idea across a whole message by XOR-ing every byte together, giving a lightweight (though not cryptographically strong) way to detect accidental corruption in a data block.

Is anything sent to a server?

No. Every computation — text/integer/float encoding, bitwise operations, parity, checksum, and batch conversion — runs entirely in your browser using plain JavaScript and the Web Crypto API's random source for the generator utility. Nothing you type ever leaves the page.
