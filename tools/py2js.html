✦ How This Tool Works

Is this a real AST-based transpiler?

It's a structural, indentation-aware line converter: it tracks Python's block nesting from whitespace the way the interpreter does, then rewrites each line's syntax with targeted pattern matching. It handles the constructs real-world scripts actually use, but it isn't a full parser — always review and test the output.

What ends up in the Diagnostics tab?

Anything Python can express that JavaScript can't map 1:1: generators (yield), multiple inheritance, decorators beyond @staticmethod/@property, context managers (with), and metaclasses. Each gets a warning pinned to its source line plus a best-effort JS approximation.

How are list/dict/set comprehensions handled?

[x*2 for x in nums if x > 0] becomes a chained .filter(x => x > 0).map(x => x * 2). Dict comprehensions become Object.fromEntries() calls, and nested comprehensions are supported one level deep before falling back to a diagnostic.

How does slicing work?

a[1:3] becomes a.slice(1, 3), a[:3] becomes a.slice(0, 3), a[-1] becomes a[a.length - 1], and a[::-1] becomes a.slice().reverse(). Step values other than 1/-1 are flagged since JS has no native strided slicing.

What do the Presets configure?

Modern ES6 favors let/const and arrow functions; Node/CommonJS wraps output in module.exports; Legacy-safe sticks to var and the function keyword for older engines; Compact strips explanatory comments for a denser diff. All are just bundles of the settings above — tweak anything after applying one.

Can I convert multiple files at once?

Yes — upload or drag in several .py files and each becomes a tab above the editor. "Download All (.zip)" converts every loaded file with your current settings and bundles the resulting .js files into one archive.

Is anything uploaded to a server?

No. Files you upload are read locally in your browser and the conversion happens entirely client-side — nothing is sent anywhere. Your draft and settings only persist in this browser's local storage.

Why doesn't my output run perfectly on the first try?

Python and JavaScript diverge on integer division, dict ordering guarantees, string immutability edge cases, and truthiness of empty containers. The converter handles the common cases correctly but real Python codebases hit long-tail idioms — treat the output as a strong first draft, not a guarantee.
