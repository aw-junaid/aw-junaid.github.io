✦ How This Tool Works

What's the difference between the four modes?

"Single Subnet" breaks one CIDR into its network, broadcast, mask and host range — the everyday lookup. "VLSM Planner" takes a base network and a list of host requirements per department or VLAN, then carves out right-sized subnets in the correct largest-first order so nothing overlaps or wastes space. "IP-in-Subnet Check" answers "does this address belong to this network?" — useful when reading firewall rules or ACLs. "CIDR Summarize" takes a list of adjacent /24s (or any prefix) and finds the smallest supernet(s) that cover them, the same aggregation logic routers use to shrink route tables.

Why does VLSM sort by host count first?

Variable-Length Subnet Masking only avoids fragmentation if the biggest requirements are placed first, since a large block can't be carved out of space already consumed by smaller ones placed earlier. Allocating largest-to-smallest against the base network is the standard textbook approach, and it's why the sort option defaults on.

What does "reserve growth headroom" actually do?

Real host counts grow. A department that needs 28 addresses today often needs 40+ in a year. This option rounds each requirement up to the next power-of-two block size beyond the minimum required, so a request for 28 hosts gets a /26 (62 usable) instead of the bare-minimum /27 (30 usable) with almost nothing left to grow into.

What's RFC 3021 mode for /31?

Normally a subnet reserves its first address for the network ID and its last for broadcast, leaving zero usable hosts in a /31 (only 2 total addresses). RFC 3021 defines a special case for point-to-point links — like router-to-router WAN links — where both addresses in a /31 are treated as usable host addresses, since there's no need for a broadcast address on a link with exactly two endpoints.

How does CIDR summarization decide what counts as "strict"?

A supernet aggregates several smaller blocks into one route, but the supernet's address range might include addresses beyond what was actually listed if the inputs don't perfectly fill it. Strict mode only proposes a summary when the input blocks exactly and completely fill the candidate supernet with no gaps and no extra space — otherwise it reports that the blocks can't be losslessly summarized and shows the tightest safe grouping instead.

Is anything sent to a server?

No. All subnet math — address parsing, masking, VLSM allocation, aggregation — runs locally in your browser using plain JavaScript bitwise operations. Nothing is uploaded, logged, or sent anywhere. Your last input and settings only persist in this browser's local storage.

Why show binary, hex, and integer forms at all?

Dotted-decimal is how humans read addresses, but subnet math itself happens in binary — the mask literally marks which bits are "network" versus "host." Seeing the octets as bits makes it obvious why a /25 splits a /24 exactly in half, and the hex/integer forms are useful for pasting into tools, firewall configs, or scripts that expect those formats directly.
