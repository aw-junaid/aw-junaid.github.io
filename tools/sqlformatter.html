✦ How This Tool Works

Why does JOIN ... ON break onto its own line, indented?

Each JOIN sits at the same indent as FROM, and its ON condition is indented one level further — the same convention used by most hand-formatted SQL, so you can scan the join graph of a query at a glance without the ON clause getting lost in a wall of text.

How are subqueries and CTEs handled?

Any (SELECT ...) or (WITH ...) — whether it's a derived table in FROM, a correlated subquery in WHERE, or a CTE body — is recursively formatted and indented one level deeper than its parent, with the closing parenthesis (and any alias after it) kept together.

What's the difference between "Break AND/OR" on and off?

On, every AND/OR-separated condition in WHERE, HAVING and ON clauses gets its own line — ideal for multi-condition filters. Off, the whole condition stays on one line after the clause keyword, which suits short queries.

Why does VARCHAR(100) have no space, but IN (SELECT ...) does?

The formatter checks whether there was whitespace between a name and its parenthesis in your original SQL. A tight function-call or type-size pattern like VARCHAR(100) or COUNT(*) stays tight; a keyword followed by a grouped expression like IN (...) or WHERE (...) gets a space, matching how each is actually written.

How does the AS keyword setting work?

"Keep as written" leaves aliases exactly as you typed them. "Always add AS" inserts it wherever an implicit alias is detected (u.name uname → u.name AS uname). "Never use AS" strips any existing AS keyword from column and table aliases.

What does the Structure tab show?

For each statement it lists the statement type (SELECT, INSERT, UPDATE, CREATE, ...) and every top-level clause found (FROM, WHERE, GROUP BY, JOIN, ...) in order — a quick way to sanity-check a large or generated query before running it.

What does "Warn on unbalanced parentheses" catch?

If a statement has more ( than ) or vice versa, the Statistics tab flags it. The formatter still renders its best-effort output so you can see roughly what's there, but the warning tells you the SQL needs a fix before you run it.

Can I format multiple files at once?

Yes — upload or drag in several .sql files and each becomes a tab above the editor. "Download All (.zip)" formats every loaded file with your current settings and bundles the results into one archive. Nothing is uploaded to a server; everything runs locally in your browser.
