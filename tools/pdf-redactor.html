PDF Redactor

A black box drawn over text in Acrobat, Preview, or a screenshot editor is cosmetic — the original text object is still sitting underneath, selectable and copy-pasteable, or trivially recovered by anyone who opens the raw PDF structure. This tool does the opposite: draw or auto-find what needs to disappear, then every marked page is rasterized to a flat image with the redaction burned in and the underlying text, fonts, and objects destroyed — not hidden.
The failure mode this exists to prevent

Real leaks — court filings, government FOIA releases, corporate disclosures — have gone out with "redacted" names still recoverable by selecting the text, copying it out, or opening the PDF's object stream. A visual box is not redaction. This tool never ships a page that still contains the original text layer underneath a mark.

How it stays true

Every marked page is rendered to a canvas at your chosen DPI, the redaction boxes are burned directly into those pixels, and the page is re-inserted as a flattened image — the original text objects, fonts, and content stream for that page are gone, not layered over. An integrity report re-opens the output and confirms no text layer remains under any marked region.

✦ How This Tool Works

Why is a black box not enough?

Drawing a rectangle over text in a PDF editor typically adds a new object on top of the page — the text object underneath is untouched. Anyone can select through the box, copy the text out, or open the file's raw content stream and read it directly. This has caused real, public redaction failures.

What does "burn" actually do?

Each marked page is rendered to a bitmap at your chosen DPI using pdf.js, the redaction boxes are painted directly into those pixels, and the page's original vector content — text, fonts, paths — is replaced with that flattened image inside the output PDF. There is no text object left to recover.

What does the integrity report check?

After burning, the tool re-opens the output file and inspects each previously-marked page for any remaining text-showing operators or extractable text under the marked regions. It reports pass/fail per check so you can confirm nothing leaked through before you send the file anywhere.

What do the auto-find patterns catch?

Built-in regex patterns for SSNs, emails, phone numbers, card numbers, IBANs, IP addresses, dates of birth, passport numbers, and MAC addresses scan the extracted text layer of every page. Matches are shown for review — nothing is auto-redacted without you checking the box.

Why remove a whole page instead of redacting it?

Some pages — a cover sheet with a full unredacted table, an exhibit that's entirely sensitive — are faster and safer to drop outright. Removed pages are deleted from the output PDF's page tree entirely, not hidden or blanked.

Is anything uploaded to a server?

No. Rendering, auto-find, burning, and the integrity re-scan all happen locally in your browser using pdf.js and pdf-lib — the PDF never leaves your machine, which matters most for exactly the sensitive documents this tool is built for.
