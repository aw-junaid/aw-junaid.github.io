✦ How This Tool Works

What problem does this actually solve?

A basic subnet calculator tells you the network and broadcast address for one CIDR block. Real subnetting work is usually the opposite direction: you're handed a host count per department or site and need to pick the tightest mask that fits, then lay all of them out inside one address block without overlap. This tool covers both — a fast mask/host converter, and a VLSM planner that does the allocation for you.

How does the VLSM planner avoid overlapping subnets?

It sorts requirements from largest to smallest host count, computes the smallest mask that satisfies each one (hosts + 2 for network/broadcast, unless you turn that off), and places each subnet immediately after the previous one ends — always aligned to a valid boundary for its own size. Largest-first ordering is standard VLSM practice because it prevents small subnets from fragmenting space a larger one needs later.

What's the difference between "Reserve network & broadcast" and the RFC 3021 option?

By default every subnet loses its first address (network) and last address (broadcast) to usable-host math. RFC 3021 carves out an exception for /31: on a point-to-point link there's no need for a broadcast address, so both addresses in a /31 can be used as host addresses — common on router-to-router WAN links to avoid wasting a full /30 on two devices.

What does "Cloud-style reservation" change?

AWS, Azure, and GCP each reserve 5 addresses per subnet instead of 2: network address, broadcast address, the VPC router, and two addresses reserved for DNS. Turning this on changes usable-host math (and therefore which mask is "smallest that fits") to match what you'd actually get when sizing a subnet in a cloud VPC rather than on-prem hardware.

Why show "subnets-per-parent" and "adjacent masks"?

When you're deciding how to carve up a /16 or /24, it helps to see how many /27s fit in a /24 (8), or what you'd get by going one bit tighter or looser than the mask you're looking at. These numbers turn an abstract prefix length into a concrete sense of how much address space you're spending.

Can I plan router-to-router links alongside LAN subnets?

Yes — turn on "Auto-append /30 links" in the VLSM planner and it inserts a small link subnet after each named requirement, sized for two point-to-point router addresses. This mirrors how real topologies mix large LAN subnets with small WAN link subnets in the same address plan.

Is anything sent to a server?

No. All mask conversion, host-count math, and VLSM allocation runs entirely in your browser. Your inputs and settings only persist in this browser's local storage so your draft survives a page reload.
