✦ How This Tool Works

What problem does this actually solve?

Modern dual-stack and transition mechanisms embed an IPv4 address inside an IPv6 address — a mapped socket address in a server log, a NAT64-translated address in a mobile carrier's network, or a legacy 6to4 or Teredo tunnel endpoint. Reading these by hand means memorizing several different bit layouts. This tool detects the scheme automatically and pulls the real IPv4 address back out, or does the reverse for testing.

Why does NAT64 need a "custom prefix" setting?

RFC 6052 defines 64:ff9b::/96 as the well-known translation prefix, but many mobile carriers and enterprise NAT64 gateways configure their own network-specific prefix instead (often a /32 or /96 out of their own allocation). If you know the operator's prefix, enter it and its length so extraction works against their addresses too.

Why is "IPv4-compatible" off by default?

The deprecated ::a.b.c.d form (RFC 4291) was retired in 2006 and its address space overlaps with other meanings, so leaving it enabled by default would cause false positives on ordinary addresses with a lot of leading zero groups. Turn it on only when you specifically expect legacy addresses.

How is a Teredo address decoded?

A Teredo address is 2001:0000::/32 + the Teredo server's IPv4 (32 bits) + flags (16 bits) + the client's UDP port XORed with 0xFFFF (16 bits) + the client's IPv4 XORed with 0xFFFFFFFF (32 bits). The obfuscation exists to stop the values from being rewritten in transit by NAT devices that scan for IPv4-looking bit patterns.

What's the difference between 6to4 and NAT64?

6to4 (2002::/16) lets an IPv6-only host reach the IPv6 internet by tunneling over IPv4, and encodes that host's own public IPv4 directly in the prefix. NAT64 does the opposite: it lets an IPv6-only client reach an IPv4-only destination, translating on the fly, with the destination's IPv4 embedded in the low bits of a synthesized IPv6 address.

Is anything sent to a server?

No, with one exception: the "Detect My Public IPv6" button is opt-in and calls a third-party API (api64.ipify.org) to look up your public address. Everything else — parsing, scheme detection, bit-level extraction, batch auditing — runs entirely in your browser. Your draft and settings only persist in this browser's local storage.

Can I audit a whole server log at once?

Yes — paste the whole file into the input box (or switch to the "Log / Batch Audit" preset first) and use the Batch Table tab, or download the results as CSV. Lines that aren't valid IPv6 are reported with an error instead of breaking the batch.
