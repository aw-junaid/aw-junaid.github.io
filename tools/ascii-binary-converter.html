✦ How This Tool Works

What problem does this actually solve?

Real binary you encounter — in CTF challenges, homework, protocol dumps, or serial logs — is rarely clean. It's often missing zero-padding, mixed with commas or dashes, split across lines, or ambiguous about whether it's 7-bit or 8-bit ASCII. This tool auto-detects bit grouping, strips stray separators, validates malformed input with a specific error location, and computes hex/octal/decimal/Base64 side by side so you don't have to guess which format your target system expects.

Why does bit width matter?

Standard ASCII fits in 7 bits (0–127), but most systems store text as 8-bit bytes with the high bit unused for plain ASCII. Old telegraph and some legacy serial protocols use true 7-bit packing, which shifts every subsequent byte's boundary if you decode it as 8-bit. Getting this wrong is the single most common reason binary "looks right" but decodes to garbage.

What does endianness mean for text?

For single-byte 8-bit ASCII, endianness is irrelevant — a byte is a byte. It matters once you're working with multi-byte units like 16-bit UTF-16 code units, where big-endian stores the most significant byte first and little-endian stores it last. Getting this backwards is a classic cause of correctly-spaced binary decoding into the wrong characters.

Why did my binary decode to gibberish or "?" characters?

The most common causes, in order: wrong bit width (7 vs 8), a stray extra or missing bit somewhere in the string throwing off every following byte's alignment, or a multi-byte UTF-8 character being decoded one byte at a time instead of as a unit. Enabling "Ignore stray separators" and "Auto-detect bit grouping" resolves the majority of real-world cases.

Is the checksum here cryptographically secure?

No — the XOR and additive checksums are simple integrity checks used in embedded systems and serial framing (like NMEA or Modbus-style sums), not security primitives. They catch accidental corruption, not deliberate tampering. For authenticated integrity, use an HMAC tool instead.

What's the difference between ASCII and UTF-8 here?

ASCII only covers code points 0–127. Any character outside that range (emoji, accented letters, non-Latin scripts) needs UTF-8, which encodes each character as 1–4 bytes. With "Encode text as UTF-8" on, this tool handles both transparently; with strict 7-bit ASCII enforced, anything outside that range is rejected instead of silently multi-byte-encoded.

Is anything sent to a server?

No. Every computation — text/binary conversion, validation, batch processing, checksums, and random generation — runs entirely in your browser. Nothing you type ever leaves the page.
