✦ How This Tool Works

What problem does this actually solve?

Verifying a file download, generating an integrity checksum, or producing an HMAC for an API signature all need the same underlying primitive computed a few different ways. This tool computes every SHA-3 family variant at once, handles files without loading the whole thing into memory first, formats output the way different tools expect (hex, Base64, colon-separated), and checks your result against an expected value automatically.

Why isn't SHA-3 in the browser's native Web Crypto API?

The SubtleCrypto API standardized around the time SHA-3 was finalized (2015) but only ever shipped SHA-1/SHA-2 digest support across browsers — SHA-3 was left out and no browser has added it natively since. This tool implements the Keccak-f[1600] permutation and the SHA-3/SHAKE sponge construction in pure JavaScript per FIPS 202, run entirely client-side, so it works without any native browser support.

What's the difference between SHA3-256 and SHAKE128?

SHA3-224/256/384/512 are fixed-output-length hash functions, direct drop-in replacements for the SHA-2 family. SHAKE128 and SHAKE256 are extendable-output functions (XOFs) — instead of a fixed digest size, you request however many output bytes you need, which is useful for key derivation, generating multiple sub-keys from one seed, or producing padding/masking material of an arbitrary length.

What's "legacy Keccak" and why does it differ from SHA3-256?

NIST changed the padding rule slightly between the original Keccak submission and the final SHA-3 standard (FIPS 202) — Keccak uses a single 0x01 padding byte where SHA-3 uses 0x06. This means Keccak-256 (as used by Ethereum and some other early adopters) and SHA3-256 produce different digests for the same input despite sharing the same underlying permutation. Both are offered here since real systems use both.

When should I use HMAC-SHA3 instead of a plain hash?

A plain hash proves a message hasn't changed, but anyone can compute it — it proves nothing about who sent the message. HMAC combines the hash function with a secret key so that only someone who knows the key can produce a valid HMAC, which is what you want for API request signing, webhook payload verification, or any scenario where you need to prove authenticity, not just integrity.

Is anything uploaded to a server?

No — text, hex input, and files are all hashed entirely in your browser using JavaScript; a file you select or drop is read locally via the File API and never leaves your device. Your draft input and settings persist only in this browser's local storage, and the HMAC key field is treated as sensitive and excluded from settings export/import and autosave.
