✦ How This Tool Works

What problem does this actually solve?

A CNAME record points one hostname at another, and that target can itself be a CNAME — chains of three or four hops aren't unusual once a CDN, load balancer, and SaaS vendor are all involved. Untangling that by hand with dig for each hop is slow, and a CNAME left pointing at a deprovisioned cloud resource is a real, actively exploited subdomain-takeover vector. This tool follows the whole chain, resolves the final address, and flags that risk automatically.

How does browser-based DNS lookup even work?

Browsers can't send raw DNS packets, so this tool uses DNS-over-HTTPS (DoH) — a standard HTTPS API that DNS resolvers like Cloudflare and Google expose. Each query is a normal HTTPS request to the resolver you choose in settings; the answer comes back as JSON.

What exactly counts as a "dangling CNAME"?

A dangling CNAME is one whose target no longer resolves — the resource it used to point to (an S3 bucket, a Heroku app, a GitHub Pages site) was deleted or unclaimed, but the CNAME pointing at it was never removed. If an attacker claims that same resource name on the target platform, traffic for your subdomain routes straight to their content.

Does a fingerprint match mean I'm definitely vulnerable?

No — it means the target pattern matches a service known to be commonly abused for takeover, which is worth investigating manually (checking whether the resource is still provisioned in your account). It is not proof of an active vulnerability, and this tool does not attempt to claim or probe the target itself.

Why compare across multiple resolvers?

After you change a DNS record, different resolvers pick up the change at different times based on cached TTLs and when they last queried the authoritative nameserver. Querying Cloudflare, Google, and Quad9 side by side is a quick way to see whether a change has fully propagated or whether some resolvers are still serving a stale answer.

Is anything sent to a server?

Yes, by necessity: every lookup is a real DNS-over-HTTPS query sent to the public resolver you select (Cloudflare, Google, or Quad9), since that's the only way a browser can perform a DNS lookup at all. No lookup data is sent anywhere else, and your input and settings only persist in this browser's local storage.

Can I check email-related records at the same time?

Yes — turn on "Also query MX records" and "Also query TXT records" in settings to pull those alongside the CNAME chain, useful when you need to confirm that repointing a hostname's CNAME won't disturb its mail routing or SPF/DKIM setup.
