✦ How This Tool Works

Why does C even need "converting" to compile as C++?

Most C already compiles as C++ — this tool isn't a compiler bridge, it's a modernizer. It rewrites the C-flavored patterns (raw malloc/free, printf, char* buffers, macro constants) into idiomatic, safer C++ equivalents, and flags the handful of constructs — implicit void* conversions, VLAs, goto-heavy control flow — that genuinely need a human decision.

How is memory management handled?

Recognized malloc/calloc/free pairs are rewritten per your ownership model: raw new/delete for a minimal diff, std::unique_ptr/std::shared_ptr for RAII with make_unique/make_shared, or std::vector for array allocations. Matching free() calls are removed automatically once ownership is smart-pointer or vector managed. realloc() is always flagged — there's no safe automatic rewrite for it.

How does the printf/scanf translation work?

The converter parses the format string itself — splitting literal text from %d/%s/%f/%x/%c specifiers — and builds the matching std::cout << chain in argument order, including std::hex and std::setprecision where needed. scanf arguments have their leading & stripped and are chained onto std::cin >>; width and skip specifiers aren't replicated, so double-check anything beyond basic reads.

What happens to struct and typedef struct?

Both single- and multi-line struct definitions — including the common typedef struct { ... } Name; pattern — are rewritten as a class Name { public: ... };, with member char* fields converted to std::string when that setting is on. Function-pointer members and bit-fields are left in place but flagged, since turning them into virtual methods or std::bitset is a judgment call.

Why flag goto, union, and variadic functions instead of rewriting them?

All three are still legal, working C++ — nothing breaks if you leave them. But they're exactly the spots where an automatic rewrite is more likely to introduce a subtle bug than fix one, so the tool leaves the code functional and puts a note in the Conversion Notes tab instead, pointing at the modern alternative (structured control flow, std::variant, variadic templates).

What's the difference between the ownership modes?

Raw new/delete is the smallest possible diff from the original C — useful when you just want C-style casts and includes modernized. unique_ptr adds automatic cleanup with single ownership and move-only transfer. shared_ptr adds reference counting, closest to a garbage-collected feel, at the cost of atomic overhead — best reserved for objects genuinely shared across owners.

Can I convert multiple files at once?

Yes — upload or drag in several .c/.h files and each becomes a tab above the editor. "Download All (.zip)" converts every loaded file with your current settings and bundles the resulting .cpp files into one archive.

Is anything uploaded to a server?

No. Files you upload are read locally in your browser and the conversion happens entirely client-side — nothing is sent anywhere. Your draft and settings only persist in this browser's local storage.
