✦ How This Tool Works

How does it decide between a property, nullable, and object fallback?

The converter samples every occurrence of a key across sibling objects (e.g. every item in an array). If the type is consistent everywhere, it's typed plainly; if it's sometimes null, it becomes nullable (T?); if it holds genuinely different JSON types across siblings — something C# has no union type for — it falls back to object (or dynamic) and gets flagged for manual review.

Why does it rename my JSON keys?

JSON commonly uses camelCase or snake_case, which isn't idiomatic C# (properties are PascalCase by convention). With PascalCase selected, properties are renamed and the original key is preserved via a [JsonPropertyName] or [JsonProperty] attribute, so serialization round-trips correctly without you tracking the mapping by hand.

System.Text.Json or Newtonsoft.Json — which should I pick?

System.Text.Json ships in the .NET runtime and is the default for ASP.NET Core, so most new projects should reach for it first. Pick Newtonsoft.Json if your project already depends on it, or you need features it still covers more completely (e.g. certain contract resolvers). "None" emits plain POCOs with zero library dependency, for when you're mapping the JSON yourself.

What does required vs nullable vs init actually change?

Nullable reference types (?) tell the compiler a value may legitimately be absent. required (C# 11+) forces the caller to set a property at construction, catching missing data at compile time instead of via a null check at runtime. init makes a property settable only during construction, so instances stay immutable afterward — useful for records or defensive DTOs.

How are duplicate/near-duplicate object shapes handled?

With "Deduplicate structurally identical classes" on, two JSON objects (even at different paths) that produce the same property names and types are collapsed into a single generated type instead of emitting near-identical classes twice — common in API responses with repeated address/contact/money shapes.

Does it detect dates, GUIDs, and enums automatically?

Yes, each independently toggleable. ISO 8601 strings become DateOnly/DateTime/DateTimeOffset; RFC 4122 strings become Guid; and string fields with a small, repeated set of values across an array (e.g. a status field) can be promoted to a generated C# enum. Note that System.Text.Json's JsonStringEnumConverter matches enum members by name, so mismatched casing between the JSON value and the generated member is flagged for a quick check.

Can I convert multiple JSON files at once?

Yes — upload or drag in several .json files and each becomes a tab above the editor. "Download All (.zip)" converts every loaded file with your current settings and bundles the resulting .cs files into one archive.

What do the built-in presets change?

API Response favors System.Text.Json with nullable types and PascalCase aliasing for resilience to schema drift. Strict/Immutable switches to record types with init-only, required properties and DataAnnotations. Config File emits plain, fully-required POCOs with no attributes. Newtonsoft-style swaps every attribute and helper method to Json.NET equivalents.

Is anything uploaded to a server?

No. Files you upload are read locally in your browser and the conversion happens entirely client-side — nothing is sent anywhere. Your draft and settings only persist in this browser's local storage.
