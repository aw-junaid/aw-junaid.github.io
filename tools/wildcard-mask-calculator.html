✦ How This Tool Works

What is a wildcard mask, and why isn't it just a subnet mask?

Cisco IOS uses wildcard masks — not subnet masks — in access-list rules, OSPF network statements, and classic EIGRP configuration. A wildcard mask is the bitwise inverse of a subnet mask: a 0 bit means "this bit must match exactly" and a 1 bit means "don't care." So 255.255.255.0 (netmask) becomes 0.0.0.255 (wildcard) for the same /24.

What's a discontiguous (non-contiguous) wildcard mask?

A normal subnet mask's 1-bits are always one contiguous block, so it always maps to a clean CIDR prefix. A wildcard mask doesn't have that restriction — IOS will accept 0.15.255.0, whose 1-bits are scattered across two octets. These are legal for matching odd, non-CIDR-aligned address patterns, but they have no equivalent /prefix notation, which is why this tool flags them separately.

How does the ACL/OSPF command generation work?

Once a network address and wildcard mask are resolved from your input, the Cisco Commands tab assembles the exact syntax IOS expects for standard and extended numbered ACLs, named ACLs, OSPF network statements, and classic EIGRP network statements — using the ACL number, name, action, and area you set in the settings panel.

How is the "matched address range" calculated?

For a contiguous wildcard mask, the range is simply the network address through network-address OR wildcard-mask (every "don't care" bit set to 1). For a discontiguous mask this single first/last range doesn't fully describe the match set, so the tool instead reports the total count of matched addresses (2 raised to the number of "don't care" bits) rather than a misleading range.

Can I build a wildcard mask that isn't a power-of-two block?

Yes — turn on "Enable manual per-octet builder" under Discontiguous Mask Builder and type any value 0–255 into each octet field. This bypasses CIDR logic entirely and lets you construct arbitrary masks like 0.31.0.255 for matching scattered address patterns some real-world ACLs actually use.

Is anything sent to a server?

No. All parsing, bit-flipping, range math, and command generation runs entirely in your browser. Your draft input and settings only persist in this browser's local storage so they survive a page reload.

Can I check whether a specific host is covered by an existing rule?

Use the IP Match Tester utility card: enter the rule's network address and wildcard mask plus the host IP you want to verify, and it reports a clear match / no-match result along with the reasoning per octet.
