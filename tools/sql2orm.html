✦ How This Tool Works

Which SQL dialects does it understand?

It parses the common subset of CREATE TABLE and CREATE INDEX syntax shared by PostgreSQL, MySQL, and SQLite — column types, NOT NULL, DEFAULT, UNIQUE, PRIMARY KEY, FOREIGN KEY ... REFERENCES, ON DELETE/ON UPDATE, and CHECK. Dialect-specific extras like ENGINE=InnoDB are ignored rather than causing an error.

How does it turn foreign keys into relationships?

Every FOREIGN KEY ... REFERENCES (inline or table-level) produces a pair of attributes: a single related object on the table holding the key, and a collection on the referenced table — wired together with back_populates (SQLAlchemy) or related_name (Django) so both sides stay in sync.

How are many-to-many join tables detected?

A table made up of exactly two foreign key columns and nothing else — the classic post_tags(post_id, tag_id) pattern — is recognized as a pure join table. Instead of generating a third model class, it becomes a secondary= association table (SQLAlchemy) or a ManyToManyField (Django) on the two real models.

What does enum detection actually catch?

A CHECK (status IN ('draft', 'published', 'archived')) constraint on a string column is recognized and turned into a proper generated Enum class (or Django choices=) instead of leaving you with a bare str and a comment.

How are auto-increment IDs and timestamps handled?

SERIAL/BIGSERIAL, MySQL's AUTO_INCREMENT, and SQL Server/Postgres IDENTITY are all recognized as auto-incrementing primary keys. Columns named like created_at or updated_at get server-side timestamp defaults (and an auto-update trigger for the latter) instead of being left as plain, unset datetimes.

What happens with SQL it can't parse?

Unrecognized statements (like ALTER TABLE or dialect-specific inline indexes) and columns that don't match a known pattern are never guessed at silently — they're listed in the Conversion Notes tab as info, warning, or manual-review items so you know exactly what to check by hand.

Can I convert several schema files at once?

Yes — upload or drag in multiple .sql files and each becomes a tab above the editor. "Download All (.zip)" converts every loaded file with your current settings and bundles the resulting model modules into one archive.

Is my schema uploaded anywhere?

No. Files you upload are read locally in your browser and the conversion happens entirely client-side — nothing is sent to a server. Your draft and settings only persist in this browser's local storage.
