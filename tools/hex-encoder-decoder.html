✦ How This Tool Works

What problem does this actually solve?

Hex shows up constantly once you're outside plain text: memory dumps, network packet captures, firmware and EEPROM contents, binary protocol fields, color codes, escape sequences in source code, and crash logs. This tool moves between readable text and its raw hex bytes in either direction, and adds the formatting rules — delimiters, grouping, prefixes — that different tools and languages expect.

Why do different tools show hex so differently?

The underlying bytes never change, but the text representation of those bytes varies by convention: Wireshark and many network tools space-delimit single bytes, C source uses \x41\x42 escapes, URLs use %41 percent-encoding, and compact protocol dumps often use no delimiter at all. The settings above cover each of these so you can match whatever you're pasting into.

What is a hex dump, and why include offsets?

A hex dump lays bytes out in fixed-width rows alongside a running byte offset and, often, an ASCII sidebar — the same layout tools like xxd or hexdump produce. The offset lets you locate a specific byte by position when comparing against a spec or reporting a bug, and the ASCII column makes it easy to spot embedded readable strings inside otherwise binary data.

Why did my decoded text show a replacement character (�)?

That symbol means the byte sequence at that position isn't valid UTF-8 — often because the hex represents binary data rather than encoded text, or because bytes were dropped or reordered somewhere upstream. Strict UTF-8 decoding, when enabled, rejects the input outright instead of substituting that character, which can be more useful when you need to know decoding failed rather than see a partial result.

Why does odd-length hex cause problems?

Every byte is exactly two hex characters, so a string with an odd number of characters is missing a nibble somewhere and can't be split into whole bytes unambiguously. Padding options let you recover a best guess — a leading zero assumes the last character is a low nibble, a trailing zero assumes it's a high nibble — but treating it as an error is usually safer when the source of the hex should be trustworthy.

Is anything sent to a server?

No. Every conversion — text-to-hex, hex-to-text, hex dumps, batch conversion, Base64 conversion, random byte generation, and hex diffing — runs entirely in your browser. Nothing you type ever leaves the page.
