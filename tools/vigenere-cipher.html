Index of Coincidence

Paste ciphertext to measure how "clumpy" its letter frequencies are. English prose sits around 0.067; a well-keyed polyalphabetic cipher drops toward 0.038, close to random — a quick signal for how long and effective the key likely is.

Kasiski Examination

Finds repeated 3–5 letter sequences in the ciphertext and the distances between their occurrences. The most common factors of those distances are strong candidates for the key length.

Key Length & Key Recovery (Chi-Squared)

Splits the ciphertext into columns for each candidate key length, then finds the Caesar shift per column that best matches standard English letter frequencies. Lower average chi-squared score means a better fit — the top candidate's recovered shifts spell out the probable key. Standard textbook cryptanalysis technique; works only against a repeating-key Vigenère, not the autokey variants above.
✦ How This Tool Works

What problem does this actually solve?

The plain-repeating-key Vigenère cipher you learn first is breakable in minutes with pen and paper once the key length is known — that's the whole point of the cryptanalysis utilities below. This tool covers both sides: encrypting/decrypting with a chosen key across three tableau variants and two autokey modes that resist that exact attack, and analyzing a ciphertext when you're the one trying to recover the key.

Why does key stream mode matter so much?

A repeating key reuses the same shift every N letters, which is exactly what Kasiski examination and Index of Coincidence detect. Autokey mode extends the key with the plaintext or ciphertext itself, so the shift never repeats and those classical attacks no longer apply — it was Vigenère's own fix for the weakness in his simpler cipher.

What's the difference between Vigenère, Beaufort, and Variant Beaufort?

All three combine a plaintext letter with a key letter using addition or subtraction around the alphabet; they differ only in which value is subtracted from which. Beaufort is self-reciprocal — the same operation both encrypts and decrypts — which made it popular for manual field cipher devices like the M-94.

How does the Index of Coincidence actually help?

It measures the probability that two randomly chosen letters in the text match. English prose has "clumpy" letter frequencies (lots of E, T, A) so it scores near 0.067; a well-keyed cipher spreads frequencies out toward the ~0.038 you'd expect from 26 equally likely letters. A value close to random suggests a longer, more effective key before you even look at the text itself.

Why try multiple key lengths in the chi-squared recovery tool?

If you split ciphertext into columns using the wrong key length, each column is really a mix of several different Caesar shifts, so no single shift fits well and the chi-squared score stays high. The correct key length is the one where every column is genuinely a single Caesar shift of English text, which shows up as a sharp drop in the average score.

Is anything sent to a server?

No. Every computation — encryption, decryption, batch processing, and all three cryptanalysis tools — runs entirely in your browser. Nothing you type ever leaves the page.
