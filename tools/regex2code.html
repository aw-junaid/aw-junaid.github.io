✦ How This Tool Works

What counts as a "catastrophic backtracking" risk?

The checker looks for nested or overlapping quantifiers — patterns like (a+)+, (a*)*, or a group containing a quantified alternation that's itself quantified. On crafted input, these can force the engine into exponential backtracking and hang the process (ReDoS). This is a heuristic, not a proof — always load-test patterns that touch untrusted input.

How are named groups turned into code?

Any (?<name>...) group is collected and, with "Generate accessors" on, the output reads captures by name (e.g. match.groups["domain"] in Python, match.Groups["domain"] in C#) instead of positional indices — so the generated code survives you reordering groups later.

Why does it warn about unanchored validation patterns?

Without ^/$ (or \A/\z in engines where $ also matches before a trailing newline), a "validate" pattern can match if the wanted text appears anywhere in the string — so "not-an-email but has a@b.co inside" would incorrectly pass. The generator flags this so you can decide if partial matching is actually what you want.

Does the raw-string setting change behavior, not just style?

Yes for languages like Python (r"...") and Go (backtick strings) — raw literals avoid double-escaping backslashes, which is where most "my regex broke when I pasted it into code" bugs come from. "Always fully escaped" is provided for languages/contexts where raw literals aren't available (e.g. inside JSON config).

What does each operation actually generate?

Validate returns a boolean. Find first match returns the first match (or null/None) with its groups. Find all matches returns a list/array of match results. Replace returns the transformed string using your replacement template. Split returns the string broken apart wherever the pattern matches.

Can I generate a unit test alongside the function?

Yes — toggle "Include a unit test stub" and it emits one test in that language's common framework (pytest for Python, Jest for JS/TS, JUnit for Java, Go's testing package, RSpec for Ruby, xUnit-style for C#, #[test] for Rust) that asserts against whatever you've typed in the test-string box.

Is anything uploaded to a server?

No. Your pattern and test string are processed entirely in your browser using each engine's native regex support (JavaScript's own RegExp drives the live tester) — nothing is sent anywhere. Your draft and settings only persist in this browser's local storage.
