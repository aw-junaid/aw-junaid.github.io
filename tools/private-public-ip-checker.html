✦ How This Tool Works

What problem does this actually solve?

Working with IPs day-to-day means constantly converting between notations, checking whether an address is routable, and doing subnet math by hand. This tool validates IPv4/IPv6 syntax, shows every common representation (binary, hex, decimal, expanded/compressed IPv6), computes network and broadcast addresses, flags private and reserved ranges before they leak into a public-facing config, and audits whole lists at once.

How is the default prefix used?

A bare address like 192.168.1.10 has no subnet information on its own. When "Assume default prefix" is on, subnet math (network, broadcast, host range) is computed using the default prefix you set — 24 for IPv4 and 64 for IPv6 out of the box, both common LAN defaults. Add an explicit /prefix to override it per line.

Why does special-use detection have individual toggles?

Different audits care about different ranges — a firewall-rule audit might only care about private vs. public, while a documentation check only cares about TEST-NET ranges. Each category (private, loopback, link-local, multicast, documentation, CGNAT, reserved) can be toggled independently so the Special-Use tab only shows what's relevant. The Summary tab's Public/Private badge always reflects the full IANA registry regardless of these toggles.

What does the Subnet Splitter actually compute?

Given a base network and a longer (more specific) prefix, it divides the address space into equal blocks — e.g. splitting a /24 into eight /27s — and lists each resulting subnet's network, broadcast, and usable range. There's a cap on how many subnets it will generate at once so an accidental huge split doesn't freeze the page.

Is the range-to-CIDR conversion exact?

Yes — an IPv4 range like 10.0.0.5-10.0.0.20 is converted into the minimal set of CIDR blocks that exactly cover that range and nothing more, using the standard bit-alignment algorithm (the same approach firewall and routing tools use to summarize address ranges).

Is anything sent to a server?

No, with one exception: the "Detect My Public IP" and "Get Geolocation" buttons are opt-in and call third-party APIs (ipify.org, ipapi.co) to look up your public IP and its rough location. Everything else — parsing, validation, subnet math, batch auditing — runs entirely in your browser. Your draft and settings only persist in this browser's local storage.

Can I check if a firewall rule is too broad?

Use the CIDR Containment Check: enter the rule's network (e.g. 10.0.0.0/8) and a specific address or smaller block you want to verify is or isn't covered. It reports containment plus the network's usable range so you can eyeball how broad the rule really is.
