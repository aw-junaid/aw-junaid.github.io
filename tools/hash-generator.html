✦ How This Tool Works

What problem does this actually solve?

Verifying a download's integrity, signing a webhook payload, or spot-checking whether two files are identical all come down to the same operation: turning data into a fixed-length fingerprint and comparing it. This tool computes that fingerprint for text or files using several standard algorithms at once, and flags a match or mismatch against a checksum you already have.

Which algorithm should I actually use?

For file integrity checks today, SHA-256 is the standard default — it's what most software distributions publish. MD5 and SHA-1 are still common in the wild (Git object IDs, legacy ZIP tools, older release pages) but are cryptographically broken for anything security-sensitive; use them only to match against an existing legacy checksum, not to protect new data. CRC32 is not cryptographic at all — it's a fast error-detection check built into formats like ZIP, PNG, and gzip, not a security tool.

Can I use this to hash passwords for storage?

No. A plain hash — even SHA-512, even with a salt you add yourself — is not designed for password storage, because it's fast to compute, which makes brute-forcing feasible. Password storage needs a slow, memory-hard function purpose-built for it, such as Argon2, bcrypt, or scrypt, implemented through a vetted library rather than assembled from a generic hash.

What's the difference between a hash and an HMAC?

A plain hash only proves data wasn't altered from a known-good copy, since anyone can compute a hash for anything. An HMAC mixes in a secret key, so it also proves the sender knew that key — which is what API request signing and webhook signature verification actually rely on.

How are large files hashed without freezing the browser?

The file is read from disk in chunks rather than loaded and hashed all at once, and the algorithms selected are applied incrementally as each chunk arrives. There's also a configurable size cap in settings so an accidentally huge file doesn't lock up the tab.

Is anything ever uploaded to a server?

No — unlike a DNS or IP lookup, hashing needs no external service at all. Every computation (MD5, SHA-family, CRC32, HMAC) runs entirely inside your browser using the Web Crypto API and local JavaScript. Files are read locally and never leave your device, and your draft input and settings only persist in this browser's local storage.
