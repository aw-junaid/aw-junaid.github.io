✦ How This Tool Works

How does it decide between a field, Optional, and Union?

The converter samples every occurrence of a key across sibling objects (e.g. every item in an array). If the type is consistent everywhere, it's typed plainly; if it's sometimes null, it becomes Optional[T]; if it holds genuinely different JSON types across siblings, it becomes a Union (or falls back to Any if that setting is off) and gets flagged for review.

Why does it rename my JSON keys?

JSON commonly uses camelCase or kebab-case, which isn't idiomatic Python (PEP 8 wants snake_case). With "snake_case" selected, fields are renamed and the original key is preserved via field(metadata={"json": "..."}) plus generated from_dict/to_dict, so serialization round-trips correctly without you tracking the mapping by hand.

What's the mutable-default problem it mentions?

In Python, def __init__(self, tags=[])-style mutable defaults are shared across every instance that doesn't override them — a classic, hard-to-debug bug. Dataclasses solve this with field(default_factory=list); this tool applies that automatically to any array/object field that ends up with a default.

How are duplicate/near-duplicate object shapes handled?

With "Deduplicate structurally identical classes" on, two JSON objects (even at different paths) that produce the same field names and types are collapsed into a single generated class instead of emitting near-identical classes twice — common in API responses with repeated address/contact/money shapes.

Does it detect dates, UUIDs, and enums automatically?

Yes, each independently toggleable. ISO 8601 strings become datetime.date/datetime.datetime with parsing wired into from_dict; RFC 4122 strings become uuid.UUID; and string fields with a small, repeated set of values across an array (e.g. a status field) can be promoted to a generated Enum class.

Can I convert multiple JSON files at once?

Yes — upload or drag in several .json files and each becomes a tab above the editor. "Download All (.zip)" converts every loaded file with your current settings and bundles the resulting .py modules into one archive.

What do the built-in presets change?

API Response favors aliasing plus from_dict/to_dict and Optional fields for resilience to schema drift. Strict/Validated adds frozen, slots, and __post_init__ checks. Config File turns off aliasing and requires all fields. Pydantic-style switches the base class to BaseModel with Field(alias=...) instead of stdlib dataclasses.

Is anything uploaded to a server?

No. Files you upload are read locally in your browser and the conversion happens entirely client-side — nothing is sent anywhere. Your draft and settings only persist in this browser's local storage.
