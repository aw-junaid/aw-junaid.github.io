✦ How This Tool Works

What problem does this actually solve?

An unfamiliar MAC address showing up in a router's client list, an ARP table, or a DHCP lease log is hard to act on by itself. This tool extracts the OUI, matches it against known manufacturers, decodes the address's bit flags, flags randomized addresses that won't match any vendor, and audits whole lists at once — turning a raw hardware identifier into something you can actually investigate.

Why does the lookup sometimes say "Unknown vendor"?

Three common reasons: the address is locally administered (software-assigned, e.g. a VM or randomized privacy MAC and was never registered to a manufacturer), the OUI belongs to a smaller or newer registrant not in the offline database, or the input isn't a real device address at all. Check the Bit Analysis tab first — a locally administered, unicast address is expected to have no vendor match.

What is a randomized / privacy MAC address?

iOS 14+, Android 10+, and most modern Wi-Fi stacks generate a new, locally administered MAC address for each network they join, specifically so the device can't be tracked across locations by its hardware address. These addresses set the U/L bit and will never match a real vendor OUI — that's expected behavior, not a sign of a spoofed or malicious device.

How is the IPv6 EUI-64 address derived?

The 48-bit MAC is split in half, the fixed 16-bit value FFFE is inserted in the middle to make it 64 bits, and the 7th bit of the first byte (the U/L bit) is flipped. That 64-bit interface identifier is then appended to any 64-bit IPv6 prefix — fe80:: for link-local, or a routed prefix for a full global address.

Can a MAC address identify a specific device or person?

No — it identifies the manufacturer (and sometimes the product line) via the OUI, not an individual device or owner. The last three bytes are a serial number the vendor assigned, but there's no public registry linking that serial back to a specific unit or person.

Is anything sent to a server?

No, with one exception: the "Online Vendor Lookup" utility is opt-in and calls a third-party API (macvendors.com) to check the full IEEE registry. Everything else — parsing, bit analysis, offline vendor matching, EUI-64 conversion, batch auditing — runs entirely in your browser. Your draft and settings only persist in this browser's local storage.

How do I use this for a rogue-device audit?

Paste your switch's MAC address table or your router's connected-clients list into the batch input. Sort by the Vendor column: a manufacturer that doesn't belong on your network (an unexpected Wi-Fi adapter brand, an SBC vendor like Raspberry Pi, or a virtualization OUI like VMware/VirtualBox on a network that should only have physical hardware) is worth investigating further.

Why generate a random MAC address?

Common legitimate uses include assigning addresses to virtual NICs, lab and test equipment, or containers without colliding with real vendor-issued hardware. The generator sets the locally-administered bit so the result is clearly non-vendor, and forces the unicast bit so it behaves like a normal single-device address unless you deliberately want a multicast one.
