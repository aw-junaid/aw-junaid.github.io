✦ How This Tool Works

What problem does this actually solve?

Before a prefix goes into a filter, a peering config, or a customer route object, it's worth knowing three things: is it syntactically valid, is it something that should never appear in the global table (a bogon), and is it actually being announced with a valid RPKI origin. This tool answers all three from one paste, plus batch-audits whole prefix lists at once.

What counts as a "bogon"?

Bogons are address blocks that should never appear in Internet routing: RFC 1918 private space, documentation ranges, link-local and loopback blocks, multicast, and other IANA-reserved space, plus private/reserved ASNs like the 64512–65534 range. Seeing one announced, or used as a route-map match, usually means a misconfiguration or a leak.

Where does the BGP and RPKI data come from?

Origin lookups, AS holder names, geolocation, and RPKI validation are fetched from RIPEstat's public data API (stat.ripe.net), which aggregates data from RIPE RIS route collectors and the five RIRs. These calls only happen when you click "Run BGP Lookup" or use one of the utility cards — validation and bogon checks never leave your browser.

Why does RPKI validation need both a prefix and an ASN?

An RPKI Route Origin Authorization (ROA) states which ASN is allowed to originate a given prefix, up to a maximum length. Validity is always evaluated for a specific (prefix, origin ASN) pair — the same prefix can be Valid for its legitimate origin and Invalid for any other ASN trying to announce it.

What does the aggregation check actually verify?

Two prefixes can be summarized into one supernet only if they're the same size, adjacent, and both fall entirely within the resulting shorter prefix's boundary. The check confirms all three conditions and reports the resulting aggregate, the same logic route summarization and route-map aggregation use.

Is anything sent to a server?

No, with one exception: BGP origin, AS holder, RPKI, geolocation, and RIS lookups are opt-in and call RIPEstat's public API (stat.ripe.net) to fetch route-collector and registry data. Input validation, bogon/martian detection, prefix math, and aggregation checks all run entirely in your browser. Your draft and settings only persist in this browser's local storage.
