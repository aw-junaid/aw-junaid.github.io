Assembly to C Converter

Paste x86-64 assembly from gcc -S -O0 — AT&T or Intel syntax, auto-detected — and recover readable, compilable C with real control-flow structuring.
Scope, honestly stated: reconstructing C from assembly is decompilation — there's no universal, always-exact algorithm for it, and tools that claim otherwise are overselling. This tool targets one well-defined, real case: unoptimized x86-64 output from gcc (-O0), which is regular enough that its control-flow idioms, stack-frame layout, and calling convention can be reliably pattern-matched back to structured C. It supports scalar int/long/float/double locals and parameters, if/else if/else, while/for loops, function calls, and printf-style output. It does not yet support arrays, structs, pointers beyond string literals, or optimized (-O1 and above) assembly — those use register allocation and instruction scheduling that break the pattern-matching this tool relies on. Anything it can't confidently resolve is left as a flagged comment rather than guessed at, and every code path in this tool's test suite was verified by compiling the output and diffing its behavior against the original program.

    ✦ How This Tool Works

    Why does this only support -O0?

    Unoptimized code follows a fixed, predictable pattern: every value lives on the stack at a known offset, and control flow uses a small set of canonical jump idioms. Optimized code reuses registers and reorders instructions in ways that make reliably recovering the original structure a much harder, less exact problem — this tool declines rather than guess at that.

    How is the control flow (if/while) recovered?

    The assembly is split into basic blocks and their jump targets, then matched against gcc's own emission patterns — a backward jump forming a loop, a conditional jump skipping past a block forming an if. Anything that doesn't match one of those shapes is left as a flagged comment instead of a guess.

    How were the results verified?

    Every supported construct was tested by compiling real C, generating its gcc -O0 assembly, feeding that assembly back through this tool, compiling the result, and diffing its runtime output against the original program.

    Is anything uploaded to a server?

    No. Files and pasted assembly are processed entirely in your browser — nothing is sent anywhere.
