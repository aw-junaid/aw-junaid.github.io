✦ How This Tool Works

What problem does this actually solve?

Diagnosing a DNS issue usually means checking several record types, across several resolvers, then cross-referencing SPF/DKIM/DMARC by hand. This tool queries every enabled record type in one pass, compares answers across resolvers to catch incomplete propagation, parses email-authentication records into their actual mechanisms, and batch-audits a whole list of domains for the same checks.

How does browser-based DNS lookup actually work?

The page sends standard DNS-over-HTTPS (RFC 8484) requests directly from your browser to the public resolver's JSON API (Cloudflare, Google, Quad9, etc.) — the same protocol your browser or OS may already use natively. No request passes through any server belonging to this site; each resolver only sees the query it directly received, exactly as if you'd queried it with dig.

Why do different resolvers sometimes disagree?

A recent DNS change hasn't reached every resolver's cache yet (propagation), a record's TTL hasn't expired everywhere, or the zone genuinely serves different answers to different networks (GeoDNS or split-horizon DNS). The Propagation tab flags disagreement so you can tell which of these you're looking at.

What does the Email Auth tab actually check?

It fetches the domain's TXT record for SPF, the _dmarc subdomain's TXT record for DMARC, and — if you provide a selector — the <selector>._domainkey subdomain for a DKIM public key. It parses SPF mechanisms (ip4/ip6/include/all) and the DMARC policy tag (p=none/quarantine/reject) so you can see enforcement level at a glance, not just whether a record exists.

What does the DNSSEC check actually confirm?

It reads the Authenticated Data (AD) flag the resolver returns in its DoH JSON response. A resolver that performs DNSSEC validation sets this flag only when the full chain of signatures (from the root down through the zone) validates correctly — so a set AD flag is a strong signal, though it reflects the resolver's own validation, not a from-scratch chain walk done in the browser.

Is anything sent to a server or logged?

No server belonging to this site is involved at all — every lookup goes straight from your browser to the DoH endpoint of the resolver you selected (Cloudflare, Google, Quad9, OpenDNS, or AdGuard), each of which has its own privacy policy for query logging. Your draft input and settings persist only in this browser's local storage.

Can I audit a list of domains at once?

Yes — enter one domain per line and click Lookup. The Batch Table tab runs the enabled record types (and, if turned on, email-auth presence checks) against every line and lets you export the whole result set as CSV, with queries capped by the concurrency limit in settings to stay resolver-friendly.
