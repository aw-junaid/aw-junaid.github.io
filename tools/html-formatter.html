✦ How This Tool Works

How does it decide what stays on one line?

Inline elements like <a>, <b>, <em> and <span> flow together with surrounding text and only wrap once a line passes your max line length. Block elements with short single-text content (like a <title> or a short <li>) also collapse onto one line automatically; anything with mixed or block-level children is expanded and indented per your settings.

What's protected from reformatting?

Content inside <pre>, <script> and <style> is always carried through byte-for-byte, and <textarea> is protected whenever "Preserve whitespace" is on — so your JS, CSS, ASCII art and default form values never get mangled by indentation or whitespace collapsing, even in Minify mode.

What does the Validation tab check?

It flags unclosed or mismatched tags (with line/column when Strict Mode is on), duplicate id attributes anywhere in the document, deprecated tags like <font> or <center>, and <img> elements missing an alt attribute for accessibility. It's a lint pass, not a full W3C validator — a good first sweep before shipping a page.

What does Strict Mode change?

With Strict Mode on, any unclosed or mismatched tag stops formatting and reports the exact line and column of the problem. With it off, the formatter still records the same issues in the Validation tab but recovers best-effort and gives you formatted output anyway — useful while a file is mid-edit.

Can I format multiple files at once?

Yes — upload or drag in several .html files and each becomes a tab above the editor. "Download All (.zip)" formats every loaded file with your current settings and bundles the results into one archive.

What do Presets and Export/Import Config do?

Presets instantly apply a bundle of settings tuned for a use case (spec-clean strict output, minified production output, CMS-safe formatting that preserves comments, or XHTML-style email templates). Export Config saves your exact settings as a JSON file your team can share and re-import for consistent output.

Is anything uploaded to a server?

No. Files you upload are read locally in your browser and formatting happens entirely client-side — nothing is sent anywhere. Your draft and settings only persist in this browser's local storage.

Why would attributes wrap onto separate lines?

When "One attribute per line when tag is long" is on and a tag's opening line would exceed your max line length with two or more attributes, each attribute gets its own indented line and the closing angle bracket drops to a new line — the same style most code formatters use for long function signatures.
