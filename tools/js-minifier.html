✦ How This Tool Works

Why keep mangling off by default?

Renaming identifiers is where most "the minifier broke my site" bugs come from — an inline onclick="doThing()", a global exposed for another script, or a name referenced via window.X will silently break if that identifier gets shortened. Mangling here only touches function-local variables and parameters unless you explicitly widen its scope.

What's the difference between "Local" and "Top-level" mangling?

Local mangling renames let/const/var/parameters that only exist inside a function body — safe because nothing outside that function can reference them by name. Top-level mangling renames names declared at the file's root scope, which is only safe if you control every consumer of this file and nothing depends on those names externally.

Why preserve /*! license */ comments even with "strip comments" on?

Many open-source licenses (MIT, BSD, Apache) require attribution to survive redistribution, including in minified bundles. Tools like Terser and UglifyJS use the /*! prefix or an @license/@preserve tag as a signal to keep a comment regardless of other settings — this tool follows the same convention.

Is it safe to strip console.log calls automatically?

Usually yes for production builds, but only if none of those calls have side effects beyond logging (e.g. console.log(x = compute()) would silently drop the assignment too). Review the removed-statement count after conversion, or turn this off if your codebase leans on that pattern.

What does the dead-code stripping option actually remove?

It targets if (false) { ... } / if (0) { ... } blocks — a common leftover from feature flags or commented-out debug paths. It's marked risky because a build-time constant that looks "false" here might be replaced with a real value by your bundler before this step ever runs, in which case stripping it early would be wrong.

Why does gzip-estimate matter if I already see the raw byte count?

Raw minified size is what you upload, but gzip/Brotli compression is what the browser actually downloads over the wire. Minification and compression attack different redundancy (token length vs. repeated patterns), so the estimated-gzip figure gives a closer read on real-world transfer savings than raw byte count alone.

Why does the tool refuse to output anything on some inputs?

With "Strict brace/paren/string balance check" on, an unbalanced { }, ( ), [ ], or an unterminated string in the source stops the run rather than silently emitting truncated or corrupted JavaScript that would fail at runtime.

Can I minify multiple files at once?

Yes — upload or drag in several .js files and each becomes a tab above the editor. "Download All (.zip)" minifies every loaded file with your current settings and bundles the resulting .min.js files into one archive. Nothing is uploaded to a server; everything runs locally in your browser.
