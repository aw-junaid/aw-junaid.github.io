✦ How This Tool Works

How does a browser do a DNS lookup?

Browsers can't send raw DNS packets, so this tool uses DNS-over-HTTPS (DoH): a plain HTTPS GET request to a public resolver's JSON API (Cloudflare, Google, Quad9). The resolver does the actual recursive DNS lookup and returns the answer as JSON, which is parsed and displayed here \u2014 no server of ours is involved.

Why compare multiple resolvers instead of trusting one?

Right after you change nameservers at your registrar, different resolvers around the world are still caching the old answer for varying lengths of time (bounded by the previous record's TTL). Querying several public resolvers at once shows you the same "some people see the old servers, some see the new ones" picture your visitors experience during a migration.

What counts as a "missing glue" record?

A nameserver is only useful if its own hostname resolves to an IP address. This tool queries A and AAAA for each advertised NS hostname through the primary resolver; if both come back empty, that nameserver can't actually be reached, which is a frequent cause of slow or failed resolution for part of your traffic.

Can this check delegation at the parent zone (registrar) directly?

Not quite \u2014 public DoH JSON APIs always answer through their own recursive resolver rather than letting you target a specific authoritative server, so this tool can't replicate a command like dig NS example.com @a.gtld-servers.net from the browser. What it can do is compare several independent resolvers' cached answers, which surfaces the same propagation and mismatch issues in practice.

Why does NS count have a recommended minimum and maximum?

A single nameserver is a single point of failure; industry guidance generally recommends at least two for redundancy. Very large NS lists (beyond roughly seven) rarely add reliability and can slow down resolution, since a resolver may need to try more servers before finding one that responds. The thresholds here are configurable rules of thumb, not hard protocol limits.

Is anything sent to a server?

Only to the public resolvers you select (Cloudflare, Google, Quad9, or a custom endpoint) to perform the actual DNS queries, and optionally to ipapi.co if you turn on the geolocation toggle for NS glue IPs. Nothing is sent to any server we operate, and no query results are stored anywhere \u2014 they exist only in your browser tab.
