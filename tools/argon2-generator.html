✦ How This Tool Works

What problem does this actually solve?

Choosing Argon2 parameters is genuinely hard: too light and you're not slowing down an attacker at all, too heavy and you stall your own login endpoint or exhaust memory on shared hosting. This tool lets you experiment with real parameters against real passwords, see the actual PHC-encoded output your server would store, verify a hash you already have, and — via the auto-tune benchmark — get a concrete iteration count for a memory budget and response-time target on your own hardware.

How is this actually computed?

Via hash-wasm, a WebAssembly build of the reference Argon2 implementation, running the exact same C code path production libraries use — nothing is simulated or approximated in JavaScript.

Argon2id, Argon2i, or Argon2d — which should I pick?

Argon2id is the hybrid variant and OWASP's default recommendation for password storage: it resists both GPU cracking (like Argon2d) and side-channel timing attacks (like Argon2i). Use Argon2i specifically if you need side-channel resistance above all else, and Argon2d only in contexts with no side-channel risk, such as offline cryptocurrency mining or key derivation with no timing-observable attacker.

What do memory, iterations, and parallelism actually control?

Memory cost (in KiB) is how much RAM the algorithm forces an attacker to use per guess — this is Argon2's main defense, since large parallel memory is expensive at scale for attackers using GPUs or ASICs. Iterations control how many passes are made over that memory, adding time cost. Parallelism controls how many independent memory lanes run concurrently, which speeds up hashing on multi-core hardware but must scale with available memory, since it's split across lanes.

Why does the same password give a different hash every time?

Because a new random salt is generated by default on every run. That's intentional: salting means two users with the same password get completely different stored hashes, which defeats precomputed rainbow-table attacks. To get a reproducible hash for testing, disable auto-generate salt and supply a fixed one.

What is the PHC-encoded string, and why does it contain the parameters?

It's a self-describing format like $argon2id$v=19$m=65536,t=3,p=4$<salt>$<hash> that bundles the algorithm, version, cost parameters, salt, and hash together. Storing this single string means you can verify a login years later even after changing your default parameters for new hashes, since each stored hash still carries the settings it was created with.

Is anything sent to a server?

No. Every computation — hashing, verification, batch hashing, benchmarking, and random salt generation — runs entirely in your browser via WebAssembly. Nothing you type, including your password, ever leaves the page. If "Never persist password" is enabled, it's also excluded from local draft autosave.
