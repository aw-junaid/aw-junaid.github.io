✦ How This Tool Works

Which YAML schema should I pick?

"Default" understands the widest range of YAML 1.1 shorthand (like yes/no as booleans). "Core" follows the stricter YAML 1.2 core schema. "JSON-compatible only" limits parsing to types JSON itself can represent. "Failsafe" treats every scalar as a plain string — useful when you don't want any implicit type conversion.

What does multi-document support do?

Many YAML files (Kubernetes manifests, CI pipelines) separate several documents with ---. Turning this on parses each one and outputs a JSON array, one entry per document, instead of only converting the first.

What are merge keys and duplicate keys?

Merge keys (<<: *anchor) pull the fields of a referenced anchor into the current map — enabled by default since it's common in config files. Duplicate keys are rejected by default to match the JSON/YAML spec; enable "Allow duplicate keys" if your source files legitimately repeat keys and you want the last one to win.

What does the Tree View and Inferred Schema show?

Tree View lays out the parsed result as an indented outline of keys, types, and values so you can scan deeply nested structures at a glance. Inferred Schema generates a best-effort JSON Schema (types, required fields, array item shapes) from your data — handy as a starting point for validation, not a substitute for a hand-written schema.

Can I convert multiple files at once?

Yes — upload or drag in several .yaml/.yml files and each becomes a tab above the editor. "Download All (.zip)" converts every loaded file with your current settings and bundles the resulting .json files into one archive.

What does Strict Mode change?

With Strict Mode on, any parse error stops conversion and shows the exact line and column of the problem. With it off, the parser still reports the error but the editor won't visually flag partial output — useful when iterating on a file you know is incomplete.

What do Presets and Export/Import Config do?

Presets instantly apply a bundle of settings tuned for a use case (API responses, config files, Kubernetes manifests, compact output). Export Config saves your exact settings as a JSON file your team can share and re-import for consistent output.

Is it safe to paste YAML from an untrusted source?

Parsing always goes through js-yaml's safe loader, which never executes code or resolves dangerous type tags — regardless of which schema you pick. On top of that, "Block prototype-pollution keys" drops __proto__/constructor/prototype keys before they reach the output object, and "Limit anchor/alias expansion" caps input size, nesting depth, and total resolved nodes so a "billion laughs"-style file can't freeze the tab. All three are on by default.

Is anything uploaded to a server?

No. Files you upload are read locally in your browser and the conversion happens entirely client-side — nothing is sent anywhere. Your draft and settings only persist in this browser's local storage.
