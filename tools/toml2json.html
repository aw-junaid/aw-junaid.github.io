✦ How This Tool Works

How are [[array-of-tables]] converted?

Every [[table]] header appends a new object to a JSON array at that key, in document order. Turn on "Collapse single-row array-of-tables" if a table that only ever appears once should come out as a plain object instead of a 1-item array.

How are dotted keys handled?

With "Expand dotted keys" on, a.b.c = 1 builds nested objects exactly as the TOML spec requires. Turn it off if you'd rather keep the literal dotted string as one flat JSON key — useful for simple lookup-table style configs.

What happens to TOML's four date/time types?

Offset date-time, local date-time, local date, and local time can each be written as an ISO 8601 string (default), split into a {date, time} object, or converted to a Unix millisecond timestamp. Since local values carry no timezone, the UTC toggle controls how they're treated only when computing a timestamp.

How are hex, octal, binary and underscored numbers handled?

0xFF, 0o17, and 0b101 are converted to plain decimal JSON numbers by default — disable that toggle to keep the original literal text instead. Underscore digit separators like 1_000_000 are always stripped before parsing, per the TOML spec.

What does Strict Mode change?

With Strict Mode on, a duplicate key, a redefined table, or malformed TOML stops conversion and shows the parser's line-numbered error. With it off, the same errors are reported, but the input editor won't be visually flagged — useful while iterating on a document you know is incomplete.

Can I convert multiple files at once?

Yes — upload or drag in several .toml files and each becomes a tab above the editor. "Download All (.zip)" converts every loaded file with your current settings and bundles the resulting .json files into one archive.

Is anything uploaded to a server?

No. Files you upload are read locally in your browser and the conversion happens entirely client-side — nothing is sent anywhere. Your draft and settings only persist in this browser's local storage.

What does the Tree View and Inferred Schema show?

Tree View lays out the converted JSON as an indented outline of keys, types, and values so you can scan deeply nested results at a glance. Inferred Schema generates a best-effort JSON Schema (types, object properties, array item shapes) from your data — a useful starting point, not a substitute for a hand-written schema.
