✦ How This Tool Works

Why does "usable" need so many settings?

Textbook subnetting says the first address is the network ID, the last is the broadcast, and everything between is usable. Real networks break that rule constantly: RFC 3021 lets a /31 use both addresses for router links, a /32 is a single host route with no broadcast concept at all, and some legacy gear still expects "subnet zero" restrictions. Each rule is a separate toggle so the math matches your actual equipment.

What does the gateway position setting change?

Most networks put the router at either the first or last usable address in a subnet — a convention, not a protocol requirement. Setting "Gateway position" tells the calculator which address to flag as the suggested gateway, and the DHCP pool is automatically calculated around it once you add reserved addresses at the start or end.

How does the VLSM planner order subnets?

Variable Length Subnet Masking works correctly only when the largest address-space requirement is allocated first; allocating in submission order can leave gaps too small for a later, bigger request. The planner sorts your list by host count descending, assigns the smallest prefix that satisfies each one, and packs them back-to-back from the base network.

What's the difference between a /31 and /30 for a WAN link?

A /30 gives 4 addresses total but only 2 are usable under classic rules — the network and broadcast address are wasted on a link that only ever has two endpoints. RFC 3021 defines the /31 specifically to remove that waste: both addresses are usable, with no network or broadcast address on the subnet at all.

How is IPv6 "usable" different from IPv4?

IPv6 subnets have no broadcast address, so there's nothing to exclude on that end. What can be excluded is the Subnet-Router anycast address — the all-zeros host address, reserved by RFC 4291 for routers on the subnet — which the "Exclude Subnet-Router anycast" toggle controls. IPv6 /127 links mirror IPv4 /31 links under RFC 6164.

Is anything sent to a server?

No. All parsing, subnet math, VLSM planning, and DHCP pool exclusion run entirely in your browser. Your draft input and settings only persist in this browser's local storage.
