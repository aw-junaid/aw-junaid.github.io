✦ How This Tool Works

What problem does this actually solve?

Hex shows up constantly when working close to bytes: firmware and network payloads, packet captures, memory dumps, encryption keys, and log lines that print raw data instead of text. This tool goes both directions — turn readable text into the exact hex bytes a protocol or byte array expects, or take hex you've copied from a terminal, a debugger, or a colleague's message and read it back as text — without needing a local script for a one-off check.

Can I paste output straight from xxd or hexdump?

Yes — enable "Strip hex-dump formatting" (on by default) and paste a full line like 00000000 48 65 6c 6c 6f |Hello| directly into the input. The leading address offset and the trailing ASCII sidebar are removed automatically before the hex is parsed, so you don't need to manually trim the line first.

Why does my hex look different from a colleague's for the same text?

The underlying bytes can be identical while the text representation differs — hex case, whether bytes are grouped or delimited, and whether each byte is prefixed with 0x or \x are all just formatting choices layered on top of the same data. This tool separates the two: the byte count and JSON output reflect the true underlying bytes regardless of how the hex string is styled.

Why do I need to pick a text encoding?

The same character can map to different bytes depending on encoding — UTF-8 represents most non-English characters using multiple bytes, Latin-1 always uses exactly one byte per character (0–255), and strict ASCII rejects anything outside the 7-bit range entirely. If your hex output doesn't match what another tool produces, a mismatched encoding is the most common cause.

What does the "escaped string" tab give me?

It renders the current bytes as a quoted string literal using common C/JavaScript/Python-style escapes — printable ASCII characters appear as themselves, and everything else (including the byte that produced the text) is written as \xNN. It's meant for pasting directly into source code as a string constant.

Is anything sent to a server?

No. Every computation — encoding, decoding, hex-dump parsing, escape-sequence decoding, and random byte generation — runs entirely in your browser. Nothing you type ever leaves the page.
