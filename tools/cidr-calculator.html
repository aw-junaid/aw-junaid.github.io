✦ How This Tool Works

Why a separate tool from a plain subnet calculator?

A single-address subnet calculator answers "what's the network and broadcast for this one CIDR?" This tool is built around the multi-block problems network engineers actually hit: designing VLSM allocations from a requirements list, collapsing dozens of routes into a clean summary, catching an overlap before a VPC peering request fails, and finding where the next block actually fits.

How does the VLSM planner decide block sizes?

Each requested host count is rounded up to the smallest power-of-two block that fits it plus the network and broadcast address (except /31 and /32, which skip that reservation). With largest-first sorting on, the biggest requirement is placed first and each next block starts at the first address boundary its size aligns to — the same manual process taught for VLSM design, just done for you.

What's the difference between "exact" and "loose" summarization?

An exact summary is the minimal list of CIDR blocks that together cover precisely the addresses you supplied — no more, no less. A single loose supernet is one CIDR block big enough to contain everything, which is simpler to advertise but may include address space you don't actually own or use. The tool shows both so you can choose based on how much unused space you're willing to include.

Why do AWS, Azure, and GCP reserve different numbers of addresses?

All three reserve the network and broadcast address like any subnet. AWS additionally reserves the VPC router, the DNS resolver, and one address for future use (5 total). Azure reserves the same four plus broadcast (5 total). GCP reserves only the network address, the default gateway, and broadcast (4 total, since GCP subnets don't broadcast a fixed DNS/router address the same way). Picking the right model before sizing a subnet avoids an under-provisioned VPC.

How does the overlap detector classify a pair?

Every pair of entered blocks is compared by their numeric start/end address range. A pair is flagged as identical if both ranges match exactly, contained if one range fully sits inside the other, overlapping if the ranges partially intersect without one containing the other, and disjoint if they share no addresses at all.

Is the next-free-subnet search guaranteed to find a valid, aligned block?

Yes — it only tests candidate starting addresses that are correctly aligned to the requested prefix length within the parent block, then checks each candidate against every used range. The first (and, if requested, next few) non-colliding, in-bounds candidates are returned in address order.
