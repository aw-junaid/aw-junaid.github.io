✦ How This Tool Works

Which serialization library should I pick?

kotlinx.serialization is the modern default for pure-Kotlin projects and multiplatform code. Moshi is a common choice on Android with Retrofit. Gson is still widely used in older Android codebases. "Plain" skips annotations entirely and generates manual fromJson/toJson helpers using org.json, if you'd rather not add a dependency.

How does it decide a property is nullable?

The converter samples every occurrence of a key across sibling objects (e.g. every item in an array). If a value is sometimes null or missing, the property becomes T? with a = null default; if the type is genuinely inconsistent across siblings (not just present/absent), it's typed Any? and flagged, since Kotlin has no built-in union type.

Why does it rename my JSON keys to camelCase?

Kotlin/JVM convention is camelCase for properties, while JSON APIs often use snake_case or kebab-case. With aliasing on, the original key is preserved via @SerialName/@Json(name=...)/@SerializedName(...) depending on the selected library, so serialization still round-trips to the exact source key.

What does @Parcelize actually require?

Enabling it adds the kotlinx.parcelize.Parcelize import and : Parcelable to every generated class, but your Android module also needs the kotlin-parcelize Gradle plugin applied — check the Setup Notes tab for the exact snippet to add.

Does it detect dates, UUIDs, and enums automatically?

Yes, each independently toggleable. ISO 8601 strings become kotlinx.datetime.Instant/LocalDate (requires the kotlinx-datetime dependency, noted in Setup Notes); RFC 4122 strings become java.util.UUID; and string fields with a small, repeated set of values across an array (e.g. a status field) can be promoted to a generated Kotlin enum class.

Why is a mixed-type field typed Any? instead of a union?

Kotlin doesn't support union types the way TypeScript does. When the same JSON key holds genuinely different types across samples (a string sometimes, a number other times), the converter falls back to Any? and flags it in Conversion Notes — usually the right long-term fix is a sealed class hierarchy with a custom serializer, which is project-specific enough to write by hand.

Can I convert multiple JSON files at once?

Yes — upload or drag in several .json files and each becomes a tab above the editor. "Download All (.zip)" converts every loaded file with your current settings and bundles the resulting .kt files into one archive.

Is anything uploaded to a server?

No. Files you upload are read locally in your browser and the conversion happens entirely client-side — nothing is sent anywhere. Your draft and settings only persist in this browser's local storage.
