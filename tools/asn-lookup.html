✦ How This Tool Works

What problem does this actually solve?

Every public IP address on the internet is originated by exactly one (usually) Autonomous System in BGP. Knowing which ASN is behind an IP, a customer, or a peer — and what else that ASN announces — is routine work for network engineers doing peering, abuse reports, traffic engineering, or troubleshooting reachability, and normally means juggling several separate lookup sites. This tool combines ASN overview, prefixes, neighbours, whois, and RPKI status in one batch-capable interface.

Where does the data come from?

Every lookup is sent live to the RIPEstat Data API (stat.ripe.net), a free public service that aggregates routing registry and BGP data from all five Regional Internet Registries, not just RIPE NCC's own region — so it covers ARIN, APNIC, LACNIC, and AFRINIC resources too. Nothing in this tool works offline; that's the trade-off for live, authoritative routing data instead of a stale local snapshot.

What does "RPKI-valid" actually mean?

Resource Public Key Infrastructure lets a prefix holder cryptographically sign a Route Origin Authorization (ROA) stating which ASN is allowed to originate their prefix. A route is "valid" if it matches a ROA, "invalid" if a ROA exists but names a different ASN or a more specific prefix than authorized, and "not found" if no ROA covers it at all — the last case isn't necessarily malicious, just unprotected.

Why do large ASNs cap the prefix/neighbour count?

Some ASNs (major clouds, transit providers) announce many thousands of prefixes and have hundreds of BGP neighbours. Rendering all of them at once would be slow and mostly unreadable, so the settings cap how many are displayed — raise the limits if you specifically need the full list, and remember the JSON tab always holds the complete API response for the focused entry.

How does "Auto-detect" tell an ASN from an IP from an org name?

A line that's purely numeric, or starts with "AS"/"ASN" followed by digits, is treated as an ASN. A line matching IPv4 or IPv6 address syntax is treated as an IP and resolved to its originating ASN first. Anything else is treated as a free-text organization name and matched against RIPEstat's search index — force a specific interpretation in settings if your input is ambiguous (e.g. a company literally named with digits).

Is anything sent to a server?

Yes, unlike some of the other tools on this site — an ASN lookup is inherently a live-data query. Every entry you type is sent to stat.ripe.net (and, for the public-IP utility card, to api.ipify.org). No account, sign-up, or API key is required by either service, and this page doesn't store your queries anywhere beyond your own browser's local storage for draft/settings persistence.

What does the generated config actually contain?

With "Generate prefix-list / route-map config" enabled, the Config tab turns the focused ASN's currently-announced prefixes into a Cisco IOS ip prefix-list or a Juniper JunOS policy-options prefix-list block under the name you choose — a common starting point for building an inbound filter for a specific customer or peer, which you should always review before deploying.
