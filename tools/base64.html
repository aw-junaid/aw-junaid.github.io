✦ How This Tool Works

Standard vs. URL-safe Base64 — which do I need?

Standard Base64 uses + and /, which have special meaning inside URLs and query strings. URL-safe Base64 swaps those for - and _ (and is usually sent without = padding) so the output can be dropped straight into a URL, cookie, or a JWT segment without escaping.

What does "Wrap as Data URI" do?

It prefixes the Base64 output with data:<mime-type>;base64,, producing a string you can paste directly into an <img src>, a CSS background-image, or a fetch call — no separate file request needed. Enable auto-detect to pull the MIME type straight from an uploaded file.

Why would I wrap Base64 output across multiple lines?

Some formats, like MIME email attachments (RFC 2045) and PEM certificates, require Base64 to be wrapped at a fixed column width — 76 characters for MIME, 64 for PEM. Long unbroken lines can also break older text tools; use the custom width option for anything else.

What does "Lenient decode" fix?

Base64 copied from emails, terminals, or PDFs often picks up stray newlines, spaces, or a data:image/png;base64, prefix. Lenient decode strips all of that automatically before decoding; turn it off if you need to see exactly why a string fails to decode.

How does the Hex View and binary output help?

Hex View shows the raw decoded (or pre-encoded) bytes in an offset / hex / ASCII layout, useful for inspecting binary formats or spotting hidden characters. When decoding to "Binary", non-text results (like images) render a live preview and download as the correct file instead of garbled text.

Can I convert multiple files at once?

Yes — switch the input to File, then upload or drag in several files; each becomes a tab above the editor. Choose a ZIP of individual .b64/decoded files, or a single JSON map of { "filename": "base64string" }, useful for bundling icon or asset data URIs.

What does Strict alphabet check do?

With it on, decoding stops at the first character outside the chosen Base64 alphabet and reports its exact position, which is the fastest way to find corruption in a copied string. With it off (and lenient decode on), invalid characters are simply skipped.

Is anything uploaded to a server?

No. Files you upload are read locally in your browser and the encoding/decoding happens entirely client-side — nothing is sent anywhere. Your draft and settings only persist in this browser's local storage.
