✦ How This Tool Works

Will this ever change what my query does?

The minifier only touches comments and whitespace outside of string literals and quoted identifiers — the content of every '...' string and "..." / `...` / [...] identifier is copied through byte-for-byte. Keyword casing is optional and cosmetic only.

What is "Preserve optimizer hints" for?

Comments like /*+ INDEX(orders idx_status) */ in Oracle or MySQL are query hints, not documentation — stripping them can silently change the execution plan. This setting keeps any /*+ ... */ block intact even when regular block comments are removed.

Why does the dialect setting matter?

Comment and identifier-quoting styles aren't universal: # comments and backtick identifiers are MySQL-specific, and bracket identifiers like [Order Date] are SQL Server-specific. Picking the right dialect (or Generic to accept all of them) stops the tokenizer from misreading ordinary SQL as a comment or identifier.

Why would I want long lines wrapped instead of one giant line?

A fully minified statement can end up as one very long line, which some log viewers, code-review diffs, and ticketing systems truncate or handle poorly. "Wrap long lines" re-introduces line breaks at safe points — after a comma, never inside a string or identifier — so the output stays a single logical statement but is easier to scan and paste.

What is the Statement Map for?

Before trusting a large minified migration or deploy script, it helps to confirm the shape survived intact. The Statement Map lists every top-level statement in order with its detected type (SELECT, INSERT, CREATE TABLE, and so on) and length, so you can spot a statement that got merged or dropped unexpectedly.

What happens to comments that get removed?

Every stripped --, # and /* */ comment is listed in the Removed Comments tab so you can double-check nothing load-bearing — a licensing header, a TODO with context, a warning to the next engineer — got thrown away silently.

Can I convert multiple files at once?

Yes — upload or drag in several .sql files and each becomes a tab above the editor. "Download All (.zip)" minifies every loaded file with your current settings and bundles the results into one archive. Nothing is uploaded to a server; everything runs locally in your browser.

What does Strict Mode catch?

An unterminated string, quoted identifier, or block comment usually means a stray quote or a truncated paste rather than valid SQL. Strict mode stops and reports where the unterminated token starts instead of guessing where it should have ended, which could otherwise swallow the rest of the script.
