✦ How This Tool Works

What problem does this actually solve?

Reverse DNS maps an IP address back to a hostname — the opposite of a normal lookup. It's used to check whether a mail server's sending IP has a matching PTR record (most receiving servers reject mail without one), to identify who owns an IP seen in server logs during an incident, and to spot dynamic or ISP-templated addresses that shouldn't be running a mail or web server.

How does the live lookup actually work?

Your browser can't make raw DNS queries directly, so this tool builds the correct in-addr.arpa (IPv4) or ip6.arpa (IPv6) query name and sends it to a public DNS-over-HTTPS resolver — Google's dns.google by default, with an optional fallback to Cloudflare's cloudflare-dns.com — and parses the PTR record from the JSON response.

What is FCrDNS and why does it matter?

Forward-Confirmed reverse DNS re-resolves the hostname you got back from the PTR record and checks that its A or AAAA record points back to the original IP. If it doesn't match, the PTR record can't be trusted as proof of ownership — anyone can point their own reverse zone at any name, but only the actual owner of a domain can make its forward record resolve back to their IP.

Why skip private IPs by default?

Addresses like 192.168.1.1 or 10.0.0.5 aren't globally routable and querying public DNS for them either times out or returns nothing useful — they only have meaning on your own network's internal DNS, if any. The tool flags them locally instead of burning a query and a timeout on every batch run.

What counts as a "generic" or templated PTR?

Many ISPs auto-generate reverse records that embed the IP itself, like 123-45-67-89.dynamic-ip.example-isp.net. These patterns are a strong signal that the address is a residential or dynamic-assignment IP rather than a dedicated server, which matters for spam filtering and abuse triage. Detection looks for the IP's octets appearing inside the hostname alongside common ISP/dynamic keywords.

Is anything sent to a server?

Yes, necessarily: an actual reverse DNS lookup requires a real DNS query, so resolving a PTR record sends the constructed query name to your chosen DoH resolver (Google or Cloudflare). The "Detect My Public IP" button separately calls ipify.org. Nothing else — parsing, batching, the arpa-name generator, and settings — runs locally, and only the query name itself (not your text or notes) ever leaves the browser.

Can I audit a whole server list at once?

Yes — paste one IP per line and click Resolve. Requests run with the concurrency limit you set so a large list doesn't hammer the resolver, results land in the Batch Table tab, and you can export the whole run as CSV for a spreadsheet or ticket.
